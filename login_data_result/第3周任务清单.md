# 第 3 周任务清单（数据驱动 + 分层设计 + Allure 报告）

> 目标：把第 2 周的"玩具套件"升级成**数据驱动、分层清晰、带可视化报告**的接口自动化框架。
> 节奏：每天 1-2 小时，**每天有可见产出，做完即打勾**。
> 本周结束你要能说：**"我的接口用例数据外置（YAML）、结构分层、能出 Allure 报告。"**

## 本周核心概念
| 概念 | 一句话解释 |
|------|-----------|
| **数据驱动（DDT）** | 用例数据放外部文件（YAML），用例只写逻辑，数据多了也不改代码 |
| **分层设计** | 分三层：**用例层**（只写断言）/ **接口层**（封装请求）/ **数据层**（YAML） |
| **Allure** | 把测试结果渲染成可视化报告的框架（步骤、用例、通过率一目了然） |

## 每天任务

### D1｜认识分层 + 建目录
- [ ] 理解三层的职责：*用例层只写断言、接口层封装请求、数据层存数据*
- [ ] 新建 `api/`、`data/`、`week03/` 三个目录
- [ ] 画出你现在的调用链：用例 → 接口 → 数据
- **产出**：目录建好 + 一张自己画的三层关系图（口头讲清即可）
- 提示：分层的目的是"改一处不用动全局"

### D2｜数据驱动第一步：读 YAML
- [ ] `pip install pyyaml`
- [ ] 建 `data/posts.yaml`，用 YAML 写几组用例数据（如不同的 userId）
- [ ] 写个小脚本把 YAML 读成 Python 对象并 print 出来
- **产出**：`posts.yaml` + 一个能读出数据的脚本
- 提示：`yaml.safe_load(文件)`；注意 `encoding='utf-8'`

### D3｜把 YAML 接进参数化
- [ ] 让 `@pytest.mark.parametrize` 的数据**来自 D2 的 YAML**（不再是写死的列表）
- [ ] 用例跑通，数据条数 = YAML 里的条数
- **产出**：一个"读 YAML + 参数化"的数据驱动用例
- 提示：把"读 YAML"封装成一个函数，parametrize 调用它

### D4｜接口层封装
- [ ] 在 `api/posts_api.py` 里把"查询帖子"等接口封装成**方法**
- [ ] 用例层**不再直接出现 URL**，改为调用接口层方法
- **产出**：用例调用 `posts_api.get_post(1)` 之类，而非拼 URL
- 提示：接口层只负责"怎么请求"，不负责"断言对不对"

### D5｜断言封装 + 日志
- [ ] 封装常用断言（如 `assert_status_ok(resp)`）
- [ ] 用 `logging` 代替 `print`，输出关键信息（请求 URL、状态、耗时）
- **产出**：断言集中在一处 + 有日志输出
- 提示：断言封装让"改断言规则"只改一个地方

### D6｜Allure 报告
- [ ] 确认装了 `allure-pytest`（没有就 `pip install allure-pytest`）
- [ ] 给用例加 Allure 装饰器：`@allure.feature` / `@allure.story` / `@allure.title` / `@allure.step`
- [ ] 跑 `pytest --alluredir=./allure-results`，再用 `allure serve ./allure-results` 打开报告
- **产出**：浏览器里能打开一份 Allure 报告，能看到用例名、步骤、通过率
- 提示：Allure 命令行需要 Java（你已装 JDK21 + allure 2.19.0）

### D7｜综合 + 复盘
- [ ] 把本周成果整合成一套：**数据驱动 + 分层 + Allure 报告**的完整套件
- [ ] 全跑一遍，Allure 报告里能看到多组数据用例
- [ ] 复盘：本周卡在哪、哪个概念还模糊、下周加强什么
- **产出**：一套完整框架 + Allure 报告截图 + 复盘
- 提示：这就是你简历上能演示的"接口自动化框架雏形"
